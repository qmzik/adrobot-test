# Adrobot

При создании кампании приложение добавляет префикс `test_lebedev_`. Например, ввод `campaign1` создаёт в Keitaro кампанию `test_lebedev_campaign1`.

Локальная форма на FastAPI и Jinja2 создаёт кампанию Keitaro с обработкой потоков по позиции. Первый поток перенаправляет выбранную страну на Google, второй отправляет остальных посетителей на один активный оффер. Страница результата появляется после независимой проверки настроек через Admin API.

## Запуск в PowerShell

Требуется Python 3.11 или новее. Из корня проекта выполните

```powershell
py -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

Введите ключ в поле `KEITARO_API_KEY` локального файла `.env`. Пример содержит URL тестового стенда и ID его домена, группы и источника. Для другого стенда замените все четыре значения. Для чтения каталога и создания кампании ключу нужны доступ к офферам, чтение и создание кампаний и потоков.

```powershell
.venv/Scripts/python -m alembic upgrade head
.venv/Scripts/python -m uvicorn main:app --host 127.0.0.1 --port 8173
```

Откройте [форму](http://127.0.0.1:8173/). Заполните название, выберите страну и активный оффер, нажмите «Создать кампанию». Каждая новая форма создаёт отдельную заявку. Результат содержит ID кампании и обоих потоков.

## Хранение и повторная отправка

Для изменения существующей кампании откройте «Редактор офферов», введите её ID, выберите поток и загрузите его из Keitaro. Добавление, исключение, возврат и закрепление доли сохраняются в черновике SQLite. Незакреплённые активные офферы получают равные части остатка. Если остаток не делится нацело, первые по порядку получают дополнительный процент. Доля последнего активного оффера должна составлять 100%.

«Отменить правки» возвращает состав к последней загрузке или подтверждённой публикации. «Опубликовать» сравнивает исходный состав с текущим через API, отправляет только список офферов выбранного потока и повторно читает его. Для публикации ключу нужно право обновления потоков. Если другая сессия уже изменила состав, загрузите свежий поток через ссылку на кампанию. При потере ответа повторная публикация проверяет, применились ли изменения.

### Локальный тестовый API с двумя офферами

В первом терминале запустите тестовый API из каталога проекта

```powershell
.venv/Scripts/python -m uvicorn tests.demo_api:app --host 127.0.0.1 --port 8174
```

Во втором терминале запустите отдельный экземпляр редактора

```powershell
$env:KEITARO_URL = 'http://127.0.0.1:8174'
$env:KEITARO_API_KEY = 'test'
$env:DATABASE_URL = 'sqlite:///./var/editor-demo.db'
.venv/Scripts/python -m alembic upgrade head
.venv/Scripts/python -m uvicorn main:app --host 127.0.0.1 --port 8175
```

Откройте [редактор тестовой кампании](http://127.0.0.1:8175/editor?campaign_id=1), загрузите поток 11 и добавьте оффер 42 к офферу 41. После публикации [ответ тестового API](http://127.0.0.1:8174/admin_api/v1/streams/11) должен содержать два значения `share: 50`. Перезапуск тестового API восстанавливает один исходный оффер с долей 100%.

### Заявки на создание

SQLAlchemy хранит заявки в SQLite (`var/adrobot.db`). Alembic применяет схему. Каждая заявка имеет уникальный идентификатор, из которого формируется alias кампании. Локальная файловая блокировка сериализует одновременные отправки одной заявки. После сбоя кнопка повтора сверяет кампанию и потоки с Keitaro и продолжает с последнего сохранённого шага. Приложение рассчитано на локальный запуск с общей папкой `var` для его процессов.

## Проверка

```powershell
.venv/Scripts/python -m pip install pytest
.venv/Scripts/python -m pytest -q
```

Тесты используют временную SQLite и подменяют Admin API. Проверяются успешное создание, повторная отправка, потеря ответа после создания потока, несовпадение сохранённой доли и ошибки ввода. Для ручной проверки на стенде отправьте форму один раз и откройте созданную кампанию по ссылке со страницы результата.
